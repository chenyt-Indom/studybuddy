## 一、大模型接入（当前默认 DeepSeek）

同时支持 **DeepSeek** 与 **中国电信星辰**，都走 OpenAI 兼容协议，适配器同一套代码。
  
在设置页切换即可，不用改代码。

### DeepSeek 参数（已核对官方文档）

| 项                       | 值                                                   |
| ----------------------- | --------------------------------------------------- |
| **Base URL（OpenAI 格式）** | **`https://api.deepseek.com/v1`**                   |
| 对话接口                    | `POST https://api.deepseek.com/v1/chat/completions` |
| 模型列表                    | `GET https://api.deepseek.com/v1/models`            |
| 鉴权                      | `Authorization: Bearer <API Key>`                   |
| **推荐模型**                | **`deepseek-flash`**（= DeepSeek-V4.1-Flash-1017）    |
| 更强但更贵                   | `deepseek-v4-pro`                                   |
| 上下文 / 最大输出              | 1M / 384K                                           |
| 拿 Key                   | <https://platform.deepseek.com/api_keys>            |
| 官方文档                    | <https://api-docs.deepseek.com/zh-cn/>              |

**模型名的坑（很重要）**

- ✅ 用 `deepseek-flash` —— 这就是 V4.1 Flash
- ⚠️ `deepseek-v4-flash` 是**已下线**的旧名，仍可调用但会兼容路由到 V4.1 Flash
- ❌ `deepseek-v4.1-flash` 这个名字**不存在**，写了会报错
- ❌ `deepseek-chat` / `deepseek-reasoner` 已在 **2026-07-24 弃用**

**思考模式（默认开启，会影响温度）**

```json
{"model": "deepseek-flash", "messages": [...],
 "thinking": {"type": "enabled"}, "reasoning_effort": "low"}
```

- 参数放在请求体根层：`{"thinking": {"type": "enabled" | "disabled"}}`
- 强度：`{"reasoning_effort": "low" | "high" | "max"}`
- ⚠️ **思考模式下 `temperature` / `presence_penalty` / `frequency_penalty` 不生效**
    
  （设置不报错，但被忽略）。所以「要温度」的场景必须显式关掉思考。
- 流式返回里思维链在 `reasoning_content`，与 `content` 同级

本项目按场景自动分配（`backend/config.py` 的 `THINKING_OFF_SCENES`）：

| 场景                   | 思考模式            | temperature | 原因          |
| -------------------- | --------------- | ----------- | ----------- |
| `tutor` 讲解           | ✅ 开（effort=low） | 不传          | 讲课质量优先，接受延迟 |
| `extract_memory` 抽记忆 | ❌ 关             | 0.1         | 要确定，不能瞎编    |
| `mine_pattern` 挖模式   | ❌ 关             | 0.2         | 要严谨推断       |
| `diagnose` 诊断        | ❌ 关             | 0.2         | 要客观         |
| `generate_quiz` 出题   | ❌ 关             | 0.8         | 要多样性，避免重复出题 |
| `report` 周报          | ❌ 关             | 0.6         | 自然但客观       |

## 二、API Key 怎么保密

你说的是「能在前端直接输入 API，并且保密」。这两件事同时成立的关键在于：

> **「前端输入」不等于「前端持有」。**
>   
> Key 提交一次就离开浏览器，之后所有调用都在后端完成。

### 数据流

```text
浏览器（输入框）
   │  只提交一次，走 127.0.0.1 回环，不出网卡
   ▼
FastAPI 后端
   │  Windows DPAPI 加密（CryptProtectData）
   ▼
data/secrets.bin   ← 密文，与「当前 Windows 用户 + 本机」绑定
   │
   └─► 调 DeepSeek 时在后端解密使用，明文永不回传浏览器
```

### 七条硬约束（改代码时别破）

1. **Key 只进不出** —— 所有接口只返回掩码 `sk-a1b2****9f8e`，绝不回传明文
2. **加密落盘** —— DPAPI 加密，拷到别的机器 / 别的 Windows 用户下解不开
3. **前端无痕** —— 不写 localStorage、不写 cookie，输入框提交后立即清空
4. **浏览器不直连大模型** —— 所有请求由后端代理，F12 的 Network 里翻不到 Key
5. **报错擦除** —— 异常信息统一过 `scrub()`，即便网关回显了 Key 也会被替换成掩码
6. **不硬编码** —— `data/` 已在 `.gitignore`，不会随仓库推上 GitHub
7. **可一键删除** —— 设置页有「删除已保存的 Key」

### 这层保护防什么、不防什么（如实说）

- ✅ 防：Key 出现在浏览器开发者工具、前端源码、localStorage、Git 提交历史、日志里
- ✅ 防：拷走 `data/` 目录到别的电脑后直接读出 Key
- ⚠️ 不防：**已经在你这台电脑上、以你的 Windows 账号运行的恶意程序**。
    
  DPAPI 是按用户隔离的，同账号的进程理论上能调用解密。要做到那一步得靠系统层面的隔离。

### 环境变量（可选，优先级更高）

临时覆盖或 CI 场景可以不落盘：

```bash
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_MODEL=deepseek-flash
```

环境变量存在时，设置页会显示「环境变量已配置」，本机存储那份不生效。

## 三、时间感知 · 联网搜索 · 深度思考

这三件事是「教学要跟得上时代」的基础设施，缺一个模型就只能凭训练记忆瞎答。

### 3.1 时间感知

每次对话都会把当前时间注入 system prompt 的**开头**（模型对开头最敏感）：

```
【当前时间】现在是 2026年10月25日 星期日 01:16（北京时间）。
当用户问「最新/今年/现在」这类问题时，以此时间为准；
如需超出你知识截止时间的信息，应说明需要联网检索或提示用户开启联网搜索。
```

实现位置：`backend/config.py` 的 `now_context()` + `backend/services/websearch.py` 的 `today_line()`。

> ⚠️ **一个 Windows 坑**：`zoneinfo.ZoneInfo("Asia/Shanghai")` 在 Windows 上需要额外装
> `tzdata` 包，没装会直接抛 `ZoneInfoNotFoundError` 把整个请求打挂（本项目踩过）。
> 中国自 1991 年起不实行夏令时，**固定 UTC+8 与 Asia/Shanghai 完全等价**，
> 所以这里做的是「优先 zoneinfo，失败降级固定 +8」，不加依赖。

### 3.2 联网搜索（DeepSeek 官方 Search 接口）

**这是独立接口，不是 chat 的参数**——这点很容易搞错：

| 项 | 值 |
| --- | --- |
| 搜索 | `POST https://api.deepseek.com/v1/tools/search` |
| 抓正文 | `POST https://api.deepseek.com/v1/tools/fetch` |
| 鉴权 | 同一个 `Authorization: Bearer <API Key>` |
| 计费 | **5 元 / 1000 次**，只有 HTTP 200 且 `results` 非空才计费 |
| 限速 | Search 100 QPS（账号级） |

请求体：

```json
{"query": "2026 广东高考数学 最新变化", "count": 6,
 "ori_question": "用户原始问题（帮助理解意图）", "need_content": false}
```

本项目用 `need_content: false`：返回的 `summary` 有 600~800 字，够模型读，比拉正文省时省钱。

**触发策略**（三种模式，前端有下拉框）：

| 模式 | 行为 |
| --- | --- |
| 自动（默认） | 命中时效线索词才查：最新/今年/政策/大纲/分数线/考试时间/报名/趋势/20\d\d … |
| 强制开启 | 每条都查 |
| 关闭 | 一条都不查 |

纯公式推导、纯定义类问题走「自动」时不会触发搜索 —— 一次搜索 0.005 元，
但更重要的是别让简单问题多等 1~2 秒。

**结果怎么用**：搜到的摘要按「权威性 + 相关度」排序后注入 system prompt，
并要求模型**用 [1] [2] 编号标注来源**；前端会在回答下方列出可点击的来源卡片。

预算是可控的：`backend/config.py` 里的 `WEB_SEARCH_COUNT`（条数）、
`WEB_SEARCH_MAX_CONTEXT`（注入上限 7000 字符）。

### 3.3 深度思考（思维链可见、可展开）

DeepSeek 思考模式的思维链在流式响应里是 `delta.reasoning_content`，与 `content` 同级。

本项目把它**单独一路推到前端**，渲染成可折叠块：

- 流式过程中实时更新「深度思考过程 · N 字」
- 点标题**展开/收起**，展开后自动滚到最新一行
- 思考中正文区只显示「深度思考中…」，不干扰阅读
- **思维链会存库**（`messages.reasoning` 字段），回翻历史时还能再展开看

### 3.4 长输出（解决「只输出一半」）

之前 `max_tokens` 固定 2048，长讲解必然被砍。现在按场景分级：

| 场景 | max_tokens |
| --- | --- |
| **tutor 讲解** | **16384** |
| 生成复习卡 | 6144 |
| 学习周报 | 4096 |
| 抽记忆 / 诊断 | 2048 |
| 挖模式 | 1536 |

DeepSeek-V4.1-Flash 的理论上限是 384K 输出，所以 16384 远没到顶。
没直接拉满的原因：给太高模型容易啰嗦，按场景给「够用就行」更稳。

改 `backend/config.py` 的 `MAX_TOKENS_MAP` 即可调整。

## 四、双层记忆库（全局 / 分科目）+ 可核查

记忆如果只是「存聊天记录」，那它就是个黑盒。这一节讲两件事：**怎么分层**，以及
**怎么让用户能看见、能纠错**。

### 4.1 为什么必须分两层

一层是「这个人是谁」，一层是「这个人在这个学科上什么样」。混在一起会出两种错：

| 错误 | 例子 |
| --- | --- |
| 学科噪声污染全局 | 把「配方法算错」当成整个人格特征，带进语文对话 |
| 全局信息到不了别的科目 | 只在数学对话里记下「视觉型学习者」，物理对话里又开始堆公式 |

所以：

| 层 | scope | 内容 | 生效范围 |
| --- | --- | --- | --- |
| **全局** | `global` | 身份、目标、作息、认知偏好、情绪基调 | **所有科目** |
| **科目** | `subject` | 该科薄弱点、理解误区、易错题型 | 只在该科 |

### 4.2 数据结构（`memories` 表）

| 字段 | 作用 |
| --- | --- |
| `scope` | `global` / `subject` |
| `subject_key` | 科目记忆才有值 |
| `content` | 一句话判断（≤40 字） |
| **`evidence`** | **触发这条记忆的原话片段 —— 可核查的关键** |
| `confidence` | 模型自评把握 0~1，**如实展示，不当事实** |
| `weight` | 记忆强度（命中↑、时间衰减） |
| `hits` | 被召回次数 |
| **`accuracy`** | **用户的判定：`unverified` / `correct` / `wrong`** |
| `pinned` | 用户置顶（永不衰减、优先注入） |
| `source` | `chat` / `manual` / `exam` / `mistake` |

### 4.3 提取：要求模型自己交代依据

Prompt 里明确要求每条都带 `evidence`（原话，10~40 字）和 `confidence`，
并禁止编造：

> evidence：从对话里摘 10~40 字**原话**作为依据，用于事后核查。不许自己编。

实测效果（demo 账号说了一段话后自动提取出 4 条全局记忆）：

```
#19 [全局][目标] 目标报考人工智能技术应用专业  置信0.95  依据:我目标是想考人工智能技术应用专业
#20 [全局][习惯] 仅晚上九点后有空学习          置信0.90  依据:平时只有晚上九点以后才有空学习
#21 [全局][偏好] 偏好图示化讲解，文字易走神    置信0.90  依据:看文字容易走神，最好多给我画图
#18 [全局][习惯] 晚上9点后注意力最好           置信1.00  依据:我一般晚上才有空学习（手动录入）
```

### 4.4 召回：被判错的记忆必须立刻失效

```
候选 = 全局记忆（无条件带上，最多 4 条）
     + 当前科目的记忆（按关键词 bigram 匹配）
     ↑
  排除 accuracy='wrong'   ← 这条是「可核查」的实际意义，不是摆设
  加权 accuracy='correct' ×1.4 、pinned ×1.3
```

去重不用精确匹配（模型每次措辞都不同），用 **字符 bigram 的 Jaccard 相似度**，
超过 **0.62** 就合并而不是新增。衰减半衰期 180 天，但 `pinned` 和 `correct` 的不衰减。

### 4.5 可核查：用户能做的六件事

记忆库页面（左侧导航「🧠 记忆库」）提供：

1. **看** —— 每条都列出：层级、类型、内容、置信度、权重、命中次数、判定状态
2. **看依据** —— 展开「依据原话：『…』」，自己判断是不是断章取义
3. **判定** —— 点「准确 / 不准确」，**判不准确的立即停止使用**
4. **改** —— 直接改内容、类型、层级、科目、依据片段
5. **加** —— 手动新增（默认置信 100%、自动置顶、不衰减）
6. **删** —— 单条删除，或「清理所有不准确」

还有 **「预览会注入什么」**：输入一个模拟问题，直接看到这次对话会用到哪些记忆、
分别是全局还是科目 —— 不是黑盒。

### 4.6 准确率怎么算（这点很容易糊弄人）

只在**有用户判定**时才计算：

- 无判定 → 返回 `null`，界面显示「尚未判定」，**不假装 100%**
- 判定数 < 3 → 显示百分比但标注「样本只有 N 条，参考价值有限」
- 判定数 ≥ 3 → 按颜色提示（≥80% 绿 / ≥60% 黄 / 否则红）

### 4.7 接口一览

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/memory` | 列表（支持 scope / subject / accuracy / 搜索） |
| GET | `/api/memory/stats` | 总数、分层、准确率、分科统计 |
| POST | `/api/memory` | 手动新增 |
| PUT | `/api/memory/{id}` | 编辑内容/类型/层级/科目/依据/置顶/判定 |
| POST | `/api/memory/{id}/verify` | 判定准确 / 不准确 / 撤销判定 |
| DELETE | `/api/memory/{id}` | 删除单条 |
| POST | `/api/memory/cleanup` | 清理所有「不准确」 |
| GET | `/api/memory/preview` | **预览某次对话会注入哪些记忆** |

### 4.8 综述层：记忆档案（原子记忆 → 分节长文）

原子记忆是一条条事实，越攒越像流水账。所以再加一层**综述**：按主题合成的连贯长文，
直接给人看，也给模型当「高层背景」（比逐条塞更省 token）。

`memory_docs` 表：`section`（学习背景/学习目标/学习习惯与偏好/各科情况/情绪与状态/近期动态）、
`content`、`version`、`auto_generated`、**`user_edited`**。

实测（demo 账号，5 节共 662 字，由 12 条原子记忆合成）：

```text
【学习背景】该生为备战 2026 年广东高考的高中生，数学科目使用全国 I 卷。
  目前数学基础存在明显薄弱环节，中档题正确率仅 20%，对数函数、二次函数、
  平面向量等知识点记忆强度降为 0%，配方法计算也容易出错……

【学习习惯与偏好】该生偏好图示化讲解，认为文字讲解容易走神……
```

### 4.9 每晚自动整理（这就是「不断更新、调整旧记忆」）

光追加不整理，记忆库迟早变成垃圾场。所以有了 **consolidate** 流程：

```text
原子记忆  ──►  LLM 整理  ──►  分节综述（重写）
                    ├──► 合并：同义多条留一条，其余标 superseded（不删，可回溯）
                    ├──► 取代：新事实覆盖旧事实（如目标变了），旧的标 superseded
                    └──► 跳过：标了 user_edited 的分节原样保留，不覆盖
```

| 触发方式 | 说明 |
| --- | --- |
| **每晚自动** | 后台任务每小时检查一次，距上次 ≥20 小时就跑（等效「每晚整理」） |
| **立即整理** | 记忆库页「立即整理」按钮 |
| **开关** | 可关闭自动整理；也可关闭「对话记忆」停止自动提取 |

**关键设计：手改优先。** 只要你手动编辑过某一节，自动整理就永远不覆盖它
（测试里专门验了：写成「E2E 手写内容，不要覆盖」，再整理一次，内容原样不动）。

**没有大模型时**走规则兜底：按类型分桶（身份/目标 → 学习背景，薄弱/误区 → 各科情况…）拼成清单，
保证离线也能整理，只是没那么像人写的。

### 4.10 管理操作（对标常见记忆产品）

| 操作 | 行为 |
| --- | --- |
| **立即整理** | 合并重复 + 归档过时 + 重写综述 |
| **编辑** | 一键进入全部节的内联编辑，保存后标记为「你手改过」 |
| **导入** | 粘贴一段现成档案文本进来，不会被自动改写 |
| **重置** | 二次确认后清空（可选只清档案 / 只清原子记忆 / 全清） |

## 五、教材版本与规范教学

「按课本教」这件事的难点不在知识点对错，而在**顺序和符号约定对不上** ——
学生翻书找不到，就会觉得"老师不是这么教的"。

### 5.1 先划清版权边界（这决定能做什么）

| 做法 | 结论 |
| --- | --- |
| 爬取教材正文全文入库 | ❌ **不做**，侵权 |
| 内置各版本**章节目录结构**（章/节/知识点顺序） | ✅ 做，属公开信息 |
| 用户导入自己手上的**正版** PDF，本地解析 | ✅ 做，**只存本机、不上传、不进 Git** |

代码里守着：`data/textbooks/` 在 `.gitignore`，bundled 教材只有结构没有正文。

### 5.2 可以选择教材版本

`backend/seeds_textbook.py` 里有一张版本注册表，按「学段 + 科目」列出真实存在的版本：

| 学科（高中） | 可选版本 |
| --- | --- |
| 数学 | 人教A版、人教B版、北师大版、苏教版、湘教版 |
| 物理 | 人教版、教科版、沪科版、粤教版、鲁科版 |
| 化学 | 人教版、苏教版、鲁科版 |
| 生物 | 人教版、苏教版、北师大版 |
| 语文 | 统编版、苏教版 |
| 英语 | 人教版、外研版、北师大版、译林版 |

每个版本标了 `builtin` 字段：

- **`builtin=true`** —— 本项目内置了该版本的公开目录结构（目前：人教A版数学 4 册、人教版物理 3 册，共 **7 本 / 90 节**）
- **`builtin=false`** —— 版本确实存在，但**目录需要你自己导入**。
  这里刻意不编造：我没法凭记忆写出北师大版每一节的标题，硬写就是给用户假数据。

### 5.3 跨册定位（这里踩了三个坑）

学生常常同时有必修一、必修二。定位必须**跨册找**，只在一册里找会漏：

```text
问「导数几何意义」→ 命中《选择性必修第二册》第五章 5.1 导数的概念及其意义
问「平抛运动」    → 命中《必修第二册》第五章 4. 抛体运动的规律
问「二次函数顶点」 → 命中《必修第一册》第二章 2.3 二次函数与一元二次方程、不等式
```

**踩过的三个坑**（都修了，写在这免得重犯）：

1. **只在"当前这一册"里找** → 问「平抛」匹配不到（它在必修二），退化成"给前几节"的废话。
   改成在该科目的**所有册次**里找，返回结果标注册次。
2. **给章标题也加分** → 第三章「函数的概念与性质」因为含「函数」二字被整体抬高，
   压过了真正该命中的 2.3 节。改成**章标题不加分**，只对节标题打分。
3. **2 字词和 4 字词同权** → 「函数」和「二次函数」得分一样，区分不出来。
   改成按词长加权（`1.2 × min(4, len)`）。

打分优先级：**知识点命中（×6）> 关键词（×3）> 节核心词（按词长加权）**。

### 5.4 导入自己的教材

两条路：

| 方式 | 说明 |
| --- | --- |
| **上传文件** | PDF / TXT / MD，`pypdf` 抽文本后按「第X章 / 第X节 / 1.2 标题」切分 |
| **粘贴目录** | 每行 `章节 \| 小节 \| 关键词`，适合没有电子版的情况 |

实测（拿一份 112 页的真实 PDF 测试）：**112 页 / 103,834 字 / 切出 92 节**。

**踩坑：康熙部首。** 很多 WPS/Word 导出的 PDF 会把「第⼀章」的「⼀」写成
Kangxi Radical（U+2F00）而不是普通「一」。不归一化就识别不出第一章、第二章。
解决：抽取后统一走 `unicodedata.normalize("NFKC", text)`。

### 5.5 「确保是最新教材」—— 我不硬编码年份

教材会改版，**内置一张"最新年份表"迟早过期；过期了还告诉用户"这是最新"，
比不检查更糟**。所以做法是：

```text
点「检查是否最新」
   → 用 DeepSeek 联网搜索：<学段><科目> <版本>教材 最新版本 修订 年份 教育部审定
   → 把检索结果交给模型判断（明确要求：资料不足就说「无法确认」，不许猜）
   → 结论 + 来源链接一起展示，由你自己确认
```

每次核查结果会存下来（`latest_check_at` / `latest_verdict` / `latest_sources`），
页面上显示「已核查过最新版本 / 尚未核查」以及上次核查时间。

> ⚠️ 说清楚：这是「**能检查**」，不是「**我保证它是最新**」。
> 教材版本这种事只有出版社和教育部说了算，任何应用都不该替他们下结论。

### 5.6 讲解时怎么用

定位到的章节会以【教材定位】注入 system prompt：

```text
【教材定位】学生用的是《人教A版 高中数学 必修第一册》（必修第一册）。
与本次问题相关的章节：
- 《必修第一册》第二章 一元二次函数、方程和不等式 / 2.3 二次函数与一元二次方程、不等式
讲解时请沿用该教材的章节顺序、术语和符号约定，必要时说明「这在你课本的哪一册哪一节」。
不要整段照抄教材原文。
```

没命中就不注入（`matched=false`），不会硬塞无关章节。

### 技术选型的两处主动偏离

1. **前端没用 Vue 3 + Element Plus + ECharts**，改成原生 JS + 手写 SVG。
     
   原因：PC 端先行验证阶段，`npm install` 在有代理问题的机器上经常装不下来，
     
   会让整套东西「跑不起来」。图表全部是手写 SVG，零 CDN、零构建，断网也能看。
     
   等三条主线验证完再迁 Vue，**后端接口一行都不用改**。
2. **记忆召回没用 ChromaDB**，改用 SQLite + 字符 bigram 重叠打分。
     
   原因：ChromaDB 会拉 onnxruntime 等一堆重依赖。召回层已经按 `recall()` 抽象好，
     
   换向量检索只改一个文件。这是明确的**降级实现，不是最终形态**。

## 十一、设计原则

1. **不做替代思考的工具** —— AI 负责讲清楚和追问，答案要学生自己组织出来
2. **数据属于用户** —— 全本地 SQLite，不联网不上传，可导出
3. **宁可少而深** —— 三个引擎跑通，胜过十个功能半成品
4. **降级要诚实** —— 没有 Key 时明确标注「离线演示」，绝不假装是真模型的回答

### v0.1.8 · 修「聊天框变形」+ 图片在气泡里裂图（2026-10-25）

用户反馈：聊天框变形了。用真浏览器逐宽度量下来，是**四个布局根因叠加**，
另外还牵出一个图标/图片的加载 bug。

**根因 1（最致命）：整页被内容顶成上万像素高**
`#app` 没有高度 → `.app { height: 100% }` 的百分比失去参照，退化成 auto
→ `.app` 的隐式 grid 行被内容撑成 14,000+ px，整页滚动、输入框被推到最底下。
修：`#app { height: 100% }` + 对话页 `.app { grid-template-rows: minmax(0,1fr) }`。

**根因 2：窄屏时对话高度是硬算的**
原 `calc(100vh - 132px)` 在标题换行（≤520px）时算不准，要么溢出要么塌；
`@media (max-width:1180px)` 里还有一句 `height: auto`，直接把 `.msgs` 撑开。
修：`.main` 变 flex 列，对话区 `flex: 1 1 auto; min-height: 0`，**不再用魔法数字**。

**根因 3：输入框被挤成一条**
`textarea` 全局是 `width: 100%`，只写 `flex: 1` 时最小宽度被撑住；
窗口一窄就把输入框压到 95px。修：`flex: 1 1 0; min-width: 0`。

**根因 4：`[hidden]` 被自己的样式顶掉**
`.attach-bar { display: flex }` 覆盖了浏览器默认的 `[hidden] { display: none }`，
没选图时也占位。修：补 `.attach-bar[hidden] { display: none }`。

**顺带修的真 bug：气泡里的图片是裂图**
`<img src="/api/chat/attachments/xxx">` **不会带 Authorization 头**，
服务端只认 Bearer → 401 → 显示成"题目图片"的破图。
修：改成带鉴权 `fetch` 取 blob 再转 objectURL（`hydrateImgs`），
历史消息也走同一条路；外加未加载时的占位尺寸，避免气泡跳动。

**窄屏适配**：≤900px 侧栏收成 64px 图标条（原来固定 216px，把对话区挤变形）。

测试：后端 105/105、前端 37/37，**新增 `tests/layout_test.cjs`**——
用无头 Edge 在 6 个宽度（1440/1280/1100/1024/820/520）真量尺寸，
拦四类回归：页面被顶高、横向溢出、发送按钮掉出视口、输入框被裁。
（jsdom 没有排版引擎，CSS 写崩了它照样全绿，所以这层必须真浏览器。）

### v0.1.7 · 对话支持上传题目图片（2026-10-25）

用户需求：聊天框能上传图片，用来学习和讲解题目。

**先查清能力，再决定怎么做（关键判断）**
- 实测官方 `GET /v1/models`：`deepseek-flash` 的 `input_modalities = ["text","image"]`，
  `deepseek-v4-pro` **只有 text**。→ 图片只对 flash 有效，不能假装所有模型都能看。
- 因此加了能力探测 `services/llm/vision.py`（现查 + 缓存 10 分钟），
  换模型后自动失效重算；不支持时**明确告诉他换模型**，而不是让请求 400 后一脸茫然。
- 也试过"本地 OCR 提文字"这条路，放弃：题目里全是公式与手写，OCR 出来是废的，
  而且要多背一个大依赖。**能原生看图就别绕**。

**链路**
- `POST /api/chat/attachments` 上传（只落本机 `data/uploads/chat/`，文件名带 `u{user_id}_` 前缀）
- `GET /api/chat/attachments/{name}` 读取，越权一律「图片不存在」，不区分是否存在（不给探测）
- 校验看**魔数**不看扩展名：`a.txt` 改名成 `a.png` 会被挡掉；单张 8MB 上限
- `messages` 新增 `attachments` 列（JSON），历史回翻还能看到当时传的图
- 组装消息时只有**最后一条用户消息**带图；另外补上最近一条带图的提问，
  这样追问（"那第二步为什么这么算"）时模型还看得到原题 —— 只补一条，避免 token 越滚越大
- Prompt 新增【题目图片】段：**先复述题目让学生确认 → 再讲 → 看不清就说看不清，不许猜数字**
- 顺手修：`truncated` 改看官方 `finish_reason == "length"`。
  原来只看字数 <40，答「红色」这种极短正确回答会被误报成「疑似截断」

**前端**
- 输入区加图片按钮（SVG 图标）+ **粘贴**（Ctrl+V 直接贴截图）+ **拖拽**（整块对话区高亮）
- 缩略图预览、可单张删除、上传中转圈；只有图片没有文字也能发（自动补"请讲解这道题"）
- 气泡里显示图片、点击放大（lightbox）；超 4 张或超 8MB 给明确提示而不是静默失败

测试：后端 105/105、前端 37/37（新增 8 项 + 5 项，含越权读取、伪装图片、带图真调模型）

### v0.1.6 · 修「教材切不过去」（2026-10-25）

用户反馈：教材没法顺利切换。复现下来是四个叠加问题，都在前端：

- **没目录的版本是一张死卡片**：版本卡里的册次按钮是「数据库里存在哪本就画哪本」，
  人教B版/北师大/苏教版/湘教版一本都没导入过 → 卡片上一个按钮都没有，点哪儿都没反应。
  现在每张卡都必有入口：有册次的列册次，没册次的给「导入这个版本的目录」，
  点了自动预填版本名 + 滚动到导入区，导入完成后自动切过去。
- **当前册永远不高亮**：比较的是册次 `code`（字符串），存的却是教材 `id`（数字），
  永远不相等。改为统一用 `code` 比较，并且切换后重新渲染版本卡。

  于是「教材不存在」也弹「已切换教材」。现在显式判 `ok === false` 并提示原因。
- **换科目会串页**：切科目时两个请求并发，慢的那个回来把新页面覆盖成旧科目的教材。
  加了序号守卫（旧响应一律丢弃），并统一「先取当前教材、再渲染版本卡」的顺序。

导入时还能带上 `edition_code`，导入的教材直接挂到该版本卡下，
不再多出一张重复的「自定义」卡。

测试：后端 97/97、前端 32/32（新增 6 项切换用例，连跑两遍结果一致）
