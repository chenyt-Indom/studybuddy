## 这是什么

StudyBuddy 是一个 **AI 驱动的个性化学习助手**，围绕「学 → 练 → 测 → 复」闭环设计，目标是用大模型 + 间隔重复算法，解决自学过程中最容易崩掉的三件事：

1. **学完就忘** —— 没有复习节奏，知识点过两周归零；
2. **错题不管** —— 错了就错了，同一个坑反复踩；
3. **没人答疑** —— 自学时卡在一个概念上，没人能立刻讲清楚。

和市面上「拍照搜题」类产品不同，StudyBuddy 的重心不在**找答案**，而在**记住答案背后的知识**。

---

## 为什么做这个

自学场景（自考 / 考证 / 转行学编程）的真实困境不是「找不到资料」，而是：

| 痛点 | 现状 | StudyBuddy 的做法 |
| --- | --- | --- |
| 学习计划定了不执行 | 计划表躺在备忘录里 | AI 按你的可用时间自动排期，每天只推「今天该做的 3 件事」 |
| 看懂了但不会做 | 视频看完感觉会了 | 强制输出：AI 追问、让你用自己的话复述 |
| 错题散落各处 | 截图存在相册深处 | 自动归集成错题本，按遗忘曲线重推 |
| 资料太杂 | PDF / PPT / 网课各一份 | 上传即解析，变成可提问的知识库 |
| 不知道自己什么水平 | 靠感觉 | 知识点掌握度量化，看得见进步曲线 |

## 核心功能

### P0 · 最小可用闭环

- **AI 答疑** —— 多轮对话式讲解，支持「换个说法再讲一遍」「举个例子」「出题考我」
- **知识库问答（RAG）** —— 上传 PDF / Word / PPT / Markdown，基于**你自己的资料**回答，带原文出处引用
- **错题本** —— 手动或拍照录入错题，AI 自动打标签、归类知识点
- **复习计划** —— 基于 SM-2 / FSRS 间隔重复算法生成每日复习队列

### P1 · 让它真正好用

- **学习计划生成** —— 输入目标（如「30 天过 CET-4」）+ 每天可用时间，自动拆成周计划 / 日任务
- **主动出题** —— 从知识库里生成选择题 / 填空题 / 简答题，自动判分
- **掌握度看板** —— 每个知识点的熟练度、遗忘风险、下次复习时间，一屏看完
- **多端同步** —— 手机端随时记，电脑端专注学

### P2 · 差异化

- **费曼模式** —— 你讲给 AI 听，AI 扮演一个「什么都要问到底的初学者」逼你把话说清楚
- **学情周报** —— 每周一封：学了什么、哪里薄弱、下周建议
- **语音问答** —— 通勤路上用说的复习
- **同伴/自习室** —— 轻量学习搭子，互相看进度

## 技术选型（初版设想）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | Python + FastAPI | 生态成熟、异步友好，与现有项目栈一致 |
| 大模型 | DeepSeek API | 中文强、价格低，适合高频问答场景 |
| 向量检索 | 先用轻量方案（如 FAISS / sqlite-vec），后续可换 | 起步不引入过重组件 |
| 数据库 | SQLite → MySQL | 单机开发先行，上量后迁移 |
| 前端 | 微信小程序 / Web SPA | 移动端优先，降低使用门槛 |
| 部署 | Docker + 云服务器 | 一键交付，便于迁移 |

> 技术栈是**设想**，不是承诺。真正开工时按实际需求再定，不做过度设计。

## 设计原则

1. **少而深** —— 宁可只有 3 个功能做到好用，不要 10 个半成品。
2. **不做替代思考的工具** —— AI 负责讲清楚和追问，答案要用户自己组织出来。
3. **数据属于用户** —— 学习记录可导出，不被平台锁死。
4. **先能用，再好看** —— 界面美化排在功能闭环之后。
